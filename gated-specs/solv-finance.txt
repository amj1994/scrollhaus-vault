Build a single-page site called **SOLV** — a dark-olive/lime fintech landing page for a
business-funding brand ("Build for fast moving business"). Recreate it EXACTLY as
specified: stack, file layout, colors, spacing, copy, and animation timing are all
intentional. Do not substitute, paraphrase, or "improve" anything.

## 1. Stack & project setup
- TanStack Start v1 (`@tanstack/react-start` + `@tanstack/react-router`) + React 19 +
  Vite (via `@lovable.dev/vite-tanstack-config`, which bundles the TanStack Start plugin,
  Tailwind v4, tsconfig-paths, and a Cloudflare-target Nitro build — do not hand-configure
  any of that) + Tailwind v4 (used only for the shadcn/ui component layer in
  `src/styles.css`; the actual page is hand-written CSS in `src/global.css`, ~3000 lines)
  + GSAP 3 + ScrollTrigger + Lenis smooth scroll.
- `vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`'s `defineConfig`, pointing
  the TanStack Start server entry at `src/server.ts`.
- `src/router.tsx` creates the router from a generated `routeTree.gen.ts` (auto-produced
  by the TanStack Router Vite plugin — do not hand-write it) with `scrollRestoration: true`
  and `defaultPreloadStaleTime: 0`.
- `src/server.ts` / `src/start.ts` wrap the TanStack Start server entry with an error
  middleware that renders a plain-text error page on any 500, instead of letting h3
  swallow it into an opaque JSON body.
- Single route: `src/routes/index.tsx` renders one component, `<Closing />` — which
  itself composes every section in order (see below) plus the footer, so the whole page
  is effectively one route tree.

## 2. Page order (all in one scrolling document)

## 5. Global scroll/reveal behavior
- Lenis smooth scroll initializes in `src/lib/useSmoothScroll.ts`, mounted once from
  `src/routes/__root.tsx`. `src/lib/gsap.ts` registers `ScrollTrigger` on GSAP exactly
  once (module-level guard). `ScrollTrigger.refresh()` is called after Lenis mounts and
  again on the window `load` event, so layout computed before web fonts/images finish
  doesn't leave triggers mis-positioned.
- Body-copy reveal pattern used throughout every section (`useXReveal.ts` hooks, one per
  section: Articles/Capital/Closing/Faq/Fee/Promo/Testimonial): each element animates
  `opacity:0, y:18px, blur(10px)` → `opacity:1, y:0, blur(0)` via its own **individual**
  ScrollTrigger with `start:"top 52%"` and `once:true` — every card/line gets its own
  trigger so a multi-item section reveals item-by-item as the user's eye actually reaches
  each one, never all at once when the section top merely touches the viewport.
- `@media (prefers-reduced-motion: reduce)` collapses all animation/transition durations
  to effectively zero (`0.001ms`) site-wide.
- Hero title intro (`useHeroIntro.ts` + `SplitText.tsx`) splits the H1 into per-word spans
  and stagger-fades them in on mount, independent of scroll.
- Partner-logo marquee (`useMarquee.ts` + `LogoMarquee.tsx`): a duplicated flex track
  animated with a linear, infinite GSAP tween (`marquee` keyframe / CSS var-driven
  `--marquee-dur`/`--marquee-shift`), so the loop is seamless. Disabled under
  reduced-motion.

## 11. Responsive behavior
- Below 900px: nav link/action pill groups hide, replaced by the mobile hamburger panel;
  hero content top-aligns instead of bottom-aligns with extra bottom padding to clear the
  now-stacked Cashflow card (which goes full-width, `left`/`right` inset instead of a
  fixed square); the vertical card-scroll decoration hides.
- 901–1335px band: several components get explicit shrink rules (spend card goes
  min-height-driven, capital photo card padding/gap tighten, testimonial quote text drops
  to 40px, etc.) — treat this as its own breakpoint, not an interpolation between the
  900px and 1440px rules.
- At and below 1335px width, both the "no spend restrictions" pill list and the partner-
  logo marquee hide every other item (`:nth-child(even)`) in both the visible set and its
  aria-hidden marquee-loop duplicate, so the row doesn't crowd once the container has
  already narrowed — sizes/gaps on the remaining items are untouched.
- ≤1440px: FAQ question/answer font sizes step down explicitly (25px / 18px).
- ≤560px: hero bottom padding increases further and the H1 drops to a fixed 2.35rem.
