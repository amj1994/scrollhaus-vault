### 5b. Scroll -> progress math (refs + rAF; zero React re-renders)
- measure(): start = window.scrollY + section.getBoundingClientRect().top; end = start + section.offsetHeight - window.innerHeight. Re-measure on resize.
- On scroll (passive): progress = clamp((scrollY - start) / (end - start), 0, 1); targetTime = progress * video.duration; applyPositions(progress, scrollPx) where scrollPx = max(0, scrollY - start).
- rAF render loop: dt = min(0.1, (now - last)/1000); smoothing = 1 - e^(-dt * 10) (LERP_TAU = 10); current += (target - current) * smoothing; snap when |target - current| < 0.002 (SNAP). If prefers-reduced-motion, pin current = 0.
  START THE LOOP DEFENSIVELY: call the same init on 'loadedmetadata' AND immediately if video.readyState >= 1. Under React StrictMode the effect mounts twice, and if you only listen for the event the second mount can miss it and the loop never starts — the canvas then freezes on one frame forever.
- Drawing: if the frame bank is ready, paint from it; otherwise seek the video: when !video.seeking && |video.currentTime - current| > 0.01, set video.currentTime = current (try/catch).

### 5c. applyPositions(progress, scrollPx)
- Hero title/caption: heroScroll = max(0, 1 - progress * 8); hero content opacity = heroScroll and transform = translateY(((1 - heroScroll) * -30)%).
- Overlay PNG: opacity = max(0, 1 - max(0, scrollPx - 150) / 30).
- Sections 2-5 occupy fifths 1-4 of progress (hero is fifth 0). For array index i (0-based), use:
  local = (progress - (i + 1)/5) / (1/5); t = 1 if local < 0, -1 if local > 1, else 1 - 2*local.
  Apply transform: translateY(t*100%); opacity = |t| < 1 ? 1 : 0; pointerEvents = |t| < 1 ? 'auto' : 'none'.
  NOTE the (i + 1): with a 0-based array a plain i/5 puts the first overlay under the hero title.

### 5e. Frame-bank scrub engine (WebCodecs + MP4Box)
Pre-decode the whole MP4 into WebP frame blobs, then blit ImageBitmaps to the canvas — falling back to video.currentTime seeking.
- Constants: LERP_TAU = 10, SNAP = 0.002, LRU_MAX = 28, LEAD = 20, WATCHDOG_MS = 45000.
- Lazy-load MP4Box from https://cdn.jsdelivr.net/npm/mp4box@0.5.2/dist/mp4box.all.min.js by injecting a <script> (resolve window.MP4Box; reuse if present).
- Start building after window 'load' (or immediately if document.readyState === 'complete'), and only once video duration is known. Skip entirely if prefers-reduced-motion or typeof VideoDecoder === 'undefined'.
- Bank state: frames: {ts, blob}[], lru: Map<index, ImageBitmap|null>, drawnIndex, ready, reverted, painted.
- Pipeline: fetch(VIDEO_URL) -> arrayBuffer -> buf.fileStart = 0 -> mp4boxfile.appendBuffer(buf) + flush(). In onReady: take info.videoTracks[0], extract the codec description from the sample-description box (avcC || hvcC || vpcC || av1C) by writing the box to a BIG_ENDIAN DataStream and taking new Uint8Array(stream.buffer, 8); configure VideoDecoder with { codec, codedWidth, codedHeight, description }; setExtractionOptions(track.id, null, { nbSamples: Infinity }); start().
  CRITICAL: in mp4box 0.5.2's UMD build MP4Box.DataStream is undefined — the constructor lives on the global as window.DataStream. Resolve it as (MP4Box.DataStream || window.DataStream), and wrap the whole onReady body in try/catch that rejects, or a throw inside the callback leaves the promise unsettled until the 45s watchdog.
- Decode with backpressure: feed EncodedVideoChunks (type: is_sync ? 'key' : 'delta'; timestamp/duration scaled by 1e6/timescale); never let more than LEAD (20) chunks be in flight ahead of completed outputs.
- Decoder output (serialized through a promise chain): draw each VideoFrame onto a lazily-sized offscreen canvas (alpha: false, codedWidth/Height, fallback 1280x720), close() the frame, then canvas.toBlob(..., 'image/webp', 0.82) and push {ts, blob}.
- Finalize: decoder.flush() -> await chain -> sort frames by ts -> createImageBitmap the nearest frame, seed the LRU, ready = true, draw immediately.
- Drawing from bank: binary-search nearestIndex over ts (microseconds vs t * 1e6); if the LRU holds that bitmap and index !== drawnIndex, ctx.drawImage(bm, 0, 0, canvas.width, canvas.height) on a 2D context created with { alpha: false }; on first paint set canvas opacity '1'. After each draw warm the LRU for i-1 .. i+2, then evict beyond 28 calling .close() on evicted bitmaps.
  NEVER evict the index currently drawn or the ones you just warmed — closing a bitmap you are about to draw throws InvalidStateError, and one throw inside the rAF callback kills the loop permanently. Wrap the draw in try/catch and keep the loop alive.
- Failure ladder: decoder error on the first (hardware) pass -> reset the bank and retry once with hardwareAcceleration: 'prefer-software'; failure on the soft pass, MP4Box error, fetch failure, no samples, or the 45s watchdog -> revert: reverted = true, ready = false, canvas opacity '0' (the raw <video> seek fallback keeps working). On unmount: abort, remove listeners, cancel rAF, close + clear all LRU bitmaps.

## 7. Asset requirements
- The hero video MUST be served with Access-Control-Allow-Origin, because MP4Box fetches it. It must also be +faststart (moov atom first) or the fetch-and-parse stalls.
- Encode: H.264 High profile, yuv420p, constant frame rate, closed GOP, keyframe about every second, at or under 1920x1080.
- The overlay PNG needs a true alpha channel and a full-bleed canvas at the hero aspect, with the subject placed so it crosses the headline band. Shoot or generate the subject against a field that keys cleanly; a pale subject on a pale ground cannot be separated by a threshold key.
