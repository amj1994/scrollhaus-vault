Build "CryptoWave — Decentralized Future Cryptocurrency Assets" — a dark, glassy crypto
wallet/exchange landing page. React 19 + Vite + TypeScript + Tailwind CSS v4 + Framer Motion.
Three sections, each built from small, single-purpose components with CSS Modules (not
Tailwind utility soup) and a carefully choreographed, hand-timed entrance sequence shared
across the whole page via one signature easing curve.

===============================================================================
STACK & ARCHITECTURE
===============================================================================
Vite + React 19 + TypeScript. Tailwind v4 wired through @tailwindcss/vite (no tailwind.config
— tokens live in plain CSS). framer-motion for every animation; no other animation library.
clsx + tailwind-merge available but barely used — almost all styling is CSS Modules
(ComponentName.module.css next to ComponentName.tsx), not Tailwind classes. This is a
components-as-files architecture: ~30 leaf components, ~30 hand-drawn inline SVG icon
components under src/components/icons/, one shared motion vocabulary under
src/components/common/.

App.tsx renders exactly three sections in a bare <main>: HeroFeatureSection, OrbitSection,
FinalSection. No router needed for the page itself — this can run as a plain Vite SPA
(mount <App/> at #root) even though the original was scaffolded on TanStack Start; nothing
on the page touches server data or routing.

SHARED MOTION VOCABULARY (src/components/common/)
===============================================================================
motionConfig.ts — ONE constant, SIGNATURE_EASE = [0.21, 1.02, 0.43, 1.01] (a cubic-bezier
with a slight overshoot — the second value exceeds 1 — so every entrance settles with a
soft spring-like ease, never a flat linear stop). Every animated element on the page uses
this same curve; it is what makes ~30 independently-built components read as one motion
language instead of a grab-bag.

motion.tsx — two reusable primitives:
  WordReveal: splits text (or explicit `lines`) into words, each wrapped in its own
    motion.span animating opacity 0->1, y:14px->0, AND filter:blur(6px)->blur(0) — text
    visibly comes into focus rather than just sliding or fading. Takes `delay` (first word)
    and `wordDelay` (stagger between words); optionally triggers on scroll-into-view instead
    of on mount.
  Reveal: a generic scroll-triggered wrapper for non-text content (cards, badges, whole
    blocks) with three variants — fade-up (y:28->0), scale (0.92->1), fade (opacity only) —
    all using SIGNATURE_EASE, once:true, configurable `amount` threshold.

TextScramble.tsx — the page's other signature text effect, distinct from WordReveal. Takes
either `text` or `lines` (array, joined with \n and rendered as stacked block spans). Once
triggered (on mount, or on scroll-into-view via useInView once:true), runs a setInterval at
`speed`ms (default 30) for `duration*1000/speed` total frames: each frame reveals
`floor(progress * text.length)` real characters from the start and fills the rest with a
random character from an alphanumeric+symbol pool, so the text appears to decrypt/resolve
left-to-right rather than fading in. Spaces and newlines are never scrambled. IMPORTANT for
capture/screenshot purposes: this effect takes `delay + duration` seconds (typically
1.2-1.4s total) to fully resolve to real text after its trigger fires — a screenshot taken
too soon after scroll will catch it mid-scramble (garbled characters), which is correct
behavior, not a bug. Wait at least 2s after scrolling a TextScramble heading into view
before capturing.

TexturedFabButton.tsx — a reusable tilted circular button (abstract-design.svg background
texture, thick dark border, inset highlight) holding a SparkleIcon; originally built for the
hero's "quick actions" FAB, reused as the corner action button on the feature-column
WalletCard variant rather than duplicating the styling.

DESIGN TOKENS (src/styles/tokens.css)
===============================================================================
Single source of truth, consumed via CSS custom properties (not Tailwind theme extension —
this app barely uses Tailwind utility classes at all). Authored against a 1440px reference
viewport with fluid clamp()-based values so the UI scales continuously from ~375px to 4K
rather than jumping at breakpoints.
  --color-bg:#060606  --color-bg-elevated:#0d0d0f  --color-panel:#0c0c0e
  --color-surface-1/2/3: white at 4%/6%/9% opacity (glass surface fills)
  --color-border-subtle/default/strong: white at 8%/14%/22% opacity
  --color-border-hairline:#22202f  --color-border-panel:#2c2d32
  --color-text-primary:#fff  --color-text-secondary: white 60%  --color-text-tertiary: white 38%
  --color-text-on-accent:#10090a
  --color-gold:#f6b03c  --color-indigo:#6562ea
  --gradient-accent: linear-gradient(128deg, gold 12%, indigo 88%) — the brand mark's core
    gradient, taken directly from the source icon SVGs
  --gradient-surface-2: a barely-there white gradient used on small glass chips/buttons and
    the balance card

Global rules (src/styles/global.css): body font-family set to Helvetica/Arial/sans-serif via
an aggressive `* { font-family: ... !important }` (deliberately overrides any font-family
set elsewhere, including the loaded Google Fonts — treat this as intentional: the design
tokens define --font-display/--font-body variables but the global override wins in
practice). Headings (h1-h3) get --font-display, 500 weight, tight tracking. Visible
2px gold focus ring on keyboard focus. Selection highlight uses --color-indigo.

===============================================================================
ACCEPTANCE
===============================================================================
- Every TextScramble and WordReveal instance fires once and settles to real, readable text
  — never leave a component mid-scramble in a static screenshot or capture.
- The WalletCard's internal reveal sequence is a single continuous timeline (computed via
  useRevealTiming's running cursor), not independently-delayed pieces that happen to overlap
  by coincidence — panel background is a hard gate before anything else starts.
- All three WalletCard instances on the page share the exact same component with different
  prop flags, not three separately-built card variants.
- Every entrance animation across all ~30 components uses SIGNATURE_EASE — an inconsistent
  easing curve anywhere is a visible regression, not a style nit.
- Zero console errors; zero horizontal overflow at any breakpoint.
- Re-host the qclay.design-hotlinked assets (icons, textures, avatar, stars background)
  before treating this as a finished, ownable asset — same caution as any third-party bucket.
